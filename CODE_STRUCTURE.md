# Clairetouati Code Structure & Coding Guidelines

This document serves as a reference for the project structure and coding standards to be followed during development.

## 📁 Project Structure

### 🌍 Root Directory
- `/app`: Contains the Next.js App Router folders and files.
  - `layout.tsx`: Root layout of the application.
  - `page.tsx`: The main landing page.
  - `globals.css`: Global styles and Tailwind directives.
- `/components`: Reusable UI components.
  - `/ui`: Low-level components (mostly generated by Shadcn).
  - `/shared`: Cross-page components like Navbar, Footer, etc.
- `/lib`: Utility functions and shared logic.
  - `utils.ts`: Contains the `cn` function for Tailwind class merging.
- `/public`: Static assets like images, fonts, and icons.

## 🛠 Tech Stack
- **Framework**: [Next.js](https://nextjs.org/) (App Router)
- **Language**: [TypeScript](https://www.typescriptlang.org/)
- **Styling**: [Tailwind CSS v4](https://tailwindcss.com/)
- **UI Components**: [Shadcn UI](https://ui.shadcn.com/)
- **Fonts**: [Inter](https://fonts.google.com/specimen/Inter)
- **Icons**: [Lucide React](https://lucide.dev/)
- **Animations**: [Framer Motion](https://www.framer.com/motion/)
- **Physics Engine**: [Matter.js](https://brm.io/matter-js/) (for complex 2D physics interactions)

## 🎨 Coding Guidelines

### 1. Component Organization
- **Atomic Components**: Place small, reusable components in `components/ui`.
- **Feature Components**: Group related components into specific sub-folders within `components/`.
- **Server vs Client**: Use `"use client"` only when necessary (e.g., for event listeners, hooks, or state).

### 2. Styling Patterns
- Use **Tailwind CSS v4** for all styling. Note that Tailwind 4 uses a CSS-first configuration located in `app/globals.css`.
- Colors are defined using **OKLCH** color space in `globals.css` for better perceptual uniformity and accessibility.
- Utilize the `cn()` utility from `@/lib/utils` for conditional class joining.
- Prefer CSS variables (defined in `globals.css`) for theme-related colors (e.g., `bg-background`, `text-primary`).

### 3. Naming Conventions
- **Files**: Use `PascalCase` for components (e.g., `Button.tsx`) and `kebab-case` for non-component files or folders (e.g., `utils.ts`, `api-handler.ts`).
- **Interfaces/Types**: Use `PascalCase` (e.g., `UserProps`).
- **Functions/Variables**: Use `camelCase`.

### 4. Animations
- Use **Framer Motion** for interactive animations and transitions.
- **Client Side**: Remember that Framer Motion components (`motion.div`, etc.) must be used within Client Components. Use `"use client"` at the top of the file when using animations.
- **Consistency**: Prefer subtle, professional animations (e.g., fades, slight slides) over overly aggressive ones unless specifically requested.

### 5. Physics & Canvas
- Use **Matter.js** for interactive physics-based UI elements.
- **Cleanup**: Always ensure physics engines and renderers are properly destroyed in the `useEffect` cleanup function to prevent memory leaks.
- **Ref Pattern**: Use `useRef` to store Matter.js engine and runner instances within components.

### 6. Development Workflow
- When adding new features, ensure they align with the existing directory hierarchy.
- For every change, refer back to this document to maintain consistency.
- Document any significant changes to this structure here.
